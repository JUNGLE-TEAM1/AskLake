# 00 4일 실행 요약

> **문서 상태 — 역사적 데모 계획 (2026-07)**
>
> 현재 제품 범위와 개발 절차는 [Product Planning](../01-product-planning.md), [Architecture](../02-architecture.md), [Development Guide](../04-development-guide.md)를 따른다.

## 최종 목표

작은 샘플 데이터라도 `Review 생성 -> ETL Job 실행 -> Catalog Dataset 확인 -> Lineage 확인 -> SQL 실행 -> Dashboard Widget 생성 -> Dashboard 저장/Publish` 흐름이 브라우저에서 끝까지 끊기지 않게 만든다.

## 핵심 데모 흐름

1. Source / Schema / Rule / Schedule / Permission / Target / Review를 확인한다.
2. Review에서 파이프라인을 생성한다.
3. ETL 목록에 새 Job이 보인다.
4. Job을 즉시 실행한다.
5. 목록 / 상세 / 실행 이력 / DAG에 같은 Run 상태가 보인다.
6. Catalog에 새 Dataset이 보인다.
7. Dataset 상세에서 schema와 lineage를 확인한다.
8. Catalog에서 Dataset을 SQL 화면으로 연다.
9. SQL 화면에서 Dataset 기준 read-only SQL을 실행한다.
10. SQL Result를 Dashboard Builder로 넘긴다.
11. Dashboard Builder에서 Table Widget을 확인하고 제목을 수정한다.
12. Widget을 추가/삭제하고 Dashboard를 저장한다.
13. Publish 후 Published 화면에서 같은 Dashboard를 확인한다.

## Pair 구성

| Pair | 책임 |
|---|---|
| Pair A - ETL Creation & Job Operations | Review 생성, Job 생성, Job 실행, Run 이력, DAG 상태 |
| Pair B - Catalog, Lineage & SQL Analysis | Dataset 목록/상세, schema, lineage, Catalog -> SQL 이동, read-only SQL 실행 |
| Pair C - Dashboard Builder & Publish | Dashboard 목록, Builder, Widget 생성/수정/삭제, 저장, Publish, Published 화면 |

## Day 1 ~ Day 4 실행표

| Day | 목표 | 종료 시 보여야 하는 상태 |
|---|---|---|
| Day 1 | 생성 결과를 ETL 목록과 Catalog에 연결하고, Catalog 상세에 기본 lineage를 보여준다. | 새 Job, 새 Dataset, Dataset schema, upstream/current/downstream lineage, Dashboard 빈 상태가 보인다. |
| Day 2 | Job 실행 상태를 이력/DAG에 연결하고, Dataset을 SQL context로 넘긴다. | 같은 Run ID가 이력/DAG에 보이고, SQL 화면에 선택 Dataset query가 채워진다. |
| Day 3 | SQL Result를 Dashboard Widget으로 넘기고, Lineage/SQL/Dashboard 조작을 보강한다. | SQL Result Preview, Lineage 선택 상태, Table Widget, Widget 제목 수정/삭제가 동작한다. |
| Day 4 | 전체 흐름을 반복 QA하고 Dashboard 저장/Publish를 완성한다. | 발표자가 5분 안에 전체 흐름을 재현하고 Published Dashboard까지 확인한다. |

## 매일 종료 조건

| Day | 종료 조건 |
|---|---|
| Day 1 | Review 생성 후 ETL 목록과 Catalog에 같은 결과가 생긴다. Dataset 상세에 schema와 기본 lineage가 보인다. Dashboard 목록/Builder 진입이 깨지지 않는다. |
| Day 2 | Job 실행 후 목록/상세/이력/DAG가 같은 Run 상태를 보여준다. Catalog에서 SQL로 열면 선택 Dataset 기준 query가 보인다. |
| Day 3 | SQL 실행 결과가 Result Preview에 보인다. Dashboard Builder에 SQL 결과 기반 Widget이 생기고 기본 편집이 된다. |
| Day 4 | Source -> ETL -> Catalog -> Lineage -> SQL -> Dashboard -> Publish 흐름이 1회 이상 끊기지 않고 통과한다. |

## 매일 회의 체크 질문

- 오늘 데모 흐름에서 끊기는 화면은 어디인가?
- `jobId`, `runId`, `datasetId`, `sqlResult.runId`, `dashboardId`가 화면 사이에서 이어지는가?
- Dataset을 바꾸면 schema, lineage, SQL query, SQL result가 같이 바뀌는가?
- Dashboard Widget은 SQL Result의 columns/rows를 실제로 쓰는가?
- 실패했을 때 입력값과 이전 상태가 유지되는가?
- 오늘 끝나야 할 화면 결과가 실제 클릭으로 확인되었는가?

## 이번 4일 동안 하지 않을 것

- 대용량 처리 성능 검증
- 모든 Source Type의 실제 연결
- Kafka 실시간 스트리밍 완성
- Spark / Trino / Kafka / Airflow 전체 운영 완성
- 인증/인가 전체 구현
- Dashboard 권한 공유 실제 저장
- 완전한 Airflow DAG 생성기
- SQL 저장, Lake 저장, CSV export 완성
- Dashboard drag/resize 완전 저장
- 서버 검색/정렬, saved query, SQL history 전체 구현
- 새 화면을 많이 추가하는 작업
